## 1. Generated models never calibrate, so the probe-miss price fallback never fires for them (OmniVoice included)
**Verdict:** CONFIRMED · **Severity:** VISIBLE

**Evidence**
- `server/src/engines/audiocpp/slot.js:540-573`: `_warm` has branches only for kokoro_tts, kitten_tts, pocket_tts, qwen3_tts (vdes / non-clone tts), qwen3_asr, voxcpm2 and chatterbox_turbo. Everything else returns `false` (:570-571).
- A generated row's `audiocpp.family` is the audio.cpp family, e.g. "omnivoice" (`generated.js:279`). OmniVoice is generated: it is not in `HAND_WIRED_FAMILIES` (`generated.js:31-35`).
- `manager.js:1966`: the whole-card difference is saved only `if (calibrated && this._prices(proc))`.
- `manager.js:1958`: a load where the probe hits also saves nothing when it is uncalibrated and has no early booking. Only a later raise-only bump after a line records a price (`:1457-1474`), and that bump returns when the probe misses (`:1458`).
- The claim is false in three places: the code comment (`manager.js:1945-1947`), the test, which uses a fake slot that answers `calibrated:true` (`server/tests/engine_vram_wiring.test.js:210-228`), and RESEARCH.md:3064-3070, which says "Since 2026-10-12 a calibrated load saves that difference".
- What was approved (TASKS:547-548): "And save the fallback card number for models whose probe fails." It sets no condition about calibration. The calibration condition appears only in BUILT (TASKS:475-477) and in commit d13d138, both written after the build.

**Refutation attempts that failed**
- No other warm-up path exists for generated rows: there is one slot class, `AudioCppSlot` (`slot.js:423`).
- The restriction is deliberate (`engine_vram_wiring.test.js:195-208`: "A load that could not calibrate saves nothing"), but nobody showed it to the user.

**Effect**
- The probe is known to miss in practice. RESEARCH:3067-3068: "the per-process card probe returned nothing at the load."
- With no price, the tab keeps saying "needs about 10 GB · more than this card has".
- With the AI model on the card, each OmniVoice load takes Auto's third step (`manager.js:940-944`, `!prior`): it unloads the AI model instead of fitting beside it.
- Combined with #8: a pin to GPU never writes a card `peak` row for such a model, so a remembered card failure is never cleared.
- Unmeasured: the spill check (`manager.js:1918`) runs before a non-warmed model's first line, so it sees only the weights.

**Surviving claim:** The approved fallback is gated on `calibrated`, which no generated engine ever returns. The OmniVoice case it was written for is not covered, while the comment, test and RESEARCH say it is.

**FIX**
1. Recommended:
   - Calibrate generated families through their own audio.cpp spec where the spec can speak without a clip. OmniVoice's spec lists `capabilities.design: ["voice_design"]` and the request option `instruction` (catalog.json). Return `calibrated:true` for those loads.
   - Correct the false claims now: the comment, the test's name and comment, and the RESEARCH line.
2. Attack:
   - Standard: yes. It reads audio.cpp's own spec (catalog.json, generated by `scripts/audiocpp-catalog.js`) rather than a list of ours. It overlaps the OPEN 2026-10-13 adoption plan (TASKS:152-157), whose build needs its own go. This belongs there.
   - It does not reach clone-only families (no design or built-in voice in the spec).
   - Option a: save the uncalibrated delta. Rejected: it measures weights only and would understate the price.
   - Option b: after the first line, save a whole-card difference. It counts other programs, the same flaw 08e8f16 removed for RAM.
   - Option c: bundle a reference clip. It adds a new asset with its own licence.
   - Open questions:
     1. The warm-up instruction text for OmniVoice and other design-capable families. The Qwen3 VoiceDesign text "A calm, clear narrator." exists, but reusing it is still a choice.
     2. The calibration length for families missing from `FAMILY_BUDGET`.
     3. What clone-only generated families do for a price (a, b, c or none).
   - Blast radius:
     - `server/src/engines/audiocpp/slot.js`: `_load` :519, `_warm` :540, `FAMILY_BUDGET` :758, `generatedSpeechRequest` :988.
     - `server/src/engines/manager.js`: load :1889-1970, `_failedOnCard` :950.
     - `server/src/engines/audiocpp/generated.js`: :279.
     - Tests: `server/tests/engine_vram_wiring.test.js` :135-144 and :195-228; `server/tests/split_and_calibration.test.js` :183-219; `server/tests/audiocpp_generated.test.js`.
     - Docs: `docs/engines.md` "Long lines, and what a model costs"; `docs/dev/RESEARCH.md` :3068-3070.
3. Surviving fix:
   - Now: correct the false "fixed for OmniVoice" claims.

   - Bring the clone-only families' price question (a/b/c/none) to the user.
