# Gap 8 — Speed on every engine: the server time-stretches what the model won't pace

## 1. What this is

Gap 8 of the audio.cpp switch ([switch plan §5](2026-10-01-audiocpp-switch.md)), the TASKS item
**"Speed works on every engine"** ([`docs/dev/TASKS.md`](../dev/TASKS.md)). Presented and
approved 2026-10-02: "your rec go" (both questions answered by the recommendation). The text
below is the plan as shown, with the answers folded in.

Speed works on every engine. A speed value can come from:
- Generate's Speed slider
- a persona's default delivery
- a render preset: Narration 1.0, Dramatic Dialogue 1.03, Quiet Reflection 0.94, Action 1.08
- one line's own delivery settings

How each engine gets it:
- **Kokoro and KittenTTS** keep pacing themselves; their models take a speed directly.
- **Qwen3, Chatterbox, Pocket TTS, and the cloud voices that ignore speed** (ElevenLabs,
  Speechify, Speechmatics) render at their own pace. The server then time-stretches the
  finished line and keeps the pitch.
- **The OpenAI-compatible provider** keeps its own speed, because it already sends one.

The stretching uses Signalsmith Stretch (`python-stretch`, MIT licence), which we already use for
pitch. Measured here: a time factor of f gives exactly 1/f of the length (0.5 doubles it, 2.0
halves it).

## 2. Changes

1. **New stretch function** in `audio/dsp`: `time_stretch(x, sr, *, factor)`, range 0.5–2.0 to
   match Generate's slider and the docs. It stays out of the effects chain, because the chain
   promises not to change a line's length. If the package is missing, the audio passes through
   unchanged and an error is logged, the same as pitch.
2. **New `speed_native` flag** on each engine's capability record, true for Kokoro and
   KittenTTS. The server checks it, and Generate reads it.
3. **`render_core.render_line`**: when speed isn't 1× and the engine doesn't pace itself, stretch
   the line. This happens after long text is joined back together and before gain and pitch.
4. **Cache key**: a stretched line's key gets a marker. Only lines cached while Speed was ignored
   re-render, once: speed ≠ 1 on an engine that doesn't pace itself. `probe_line_cached` gets the
   same marker, because the two must build the same key.
5. **`/v1/generate`** (both of its synth paths) uses the same stretch, through one function shared
   with `render_core`, so Generate and a chapter render sound the same. **Answer A: yes** — the
   shared function carries Pitch and Gain too, so Generate's Pitch and Gain sliders work (§4).
6. **A hint under Generate's Speed slider**, like the one Pitch has. **Answer B, the words:**
   - Kokoro, KittenTTS: "Native — the engine paces itself."
   - Every other engine: "Post-process — the rendered audio is time-stretched, pitch kept."
7. **Docs**: `generate.md` (it says "the other engines ignore it"); `engines.md` and
   `code-map.md` §3b; the switch plan — mark gap 8 done in §5; TASKS.
8. **Tests**: the stretched length matches the speed; a line on an engine without its own speed
   gets stretched, and a Kokoro line doesn't; the cache marker; Generate stretches.
9. **Checks**: gates — ruff, pytest, vitest, biome, vite build, and the smoke test on the real
   data dir. Live — in the real app, render one Qwen3 or Pocket line at 0.8× and 1.25× and
   measure the durations.

**Not in gap 8:** inline `[speed:0.7]…[/speed]` tags, which are still stripped, and voice
previews, which still play at the engine's own pace.

## 4. Found on the way (already there before this work)

**Generate never applied Pitch or Gain.** `/v1/generate` sent the delivery settings to the engine
and applied only the effects chain. Pitch and Gain were applied only in `render_core`
(`render_core.py:745`, `:759` at the time), and no engine reads them. So both sliders did nothing
in Generate, while `generate.md` said they work on every engine. Chapter renders were fine.
Answer A folds the fix into this change.
